# Analisis Comparativo
## Lenguaje elegido: Python

En C no existe el concepto de string como tal, sino que es un arreglo de caracteres (`char`) que debe terminar en `“\0”`. Si bien posee bibliotecas para facilitar la manipulación de estos arreglos, ninguna los convierte en un tipo de dato independiente, a diferencia de lenguajes de más alto nivel como podría ser Python, el cual posee strings como tipo de dato primitivo.

En el caso de C para manipular estos arreglos la biblioteca estándar provee `<string.h>`, que incluye funciones como `strcpy`, `strlen`, `strcat`, etc. las cuales operan mediante punteros hasta encontrar el `“\0”`. En cambio, Python no requiere bibliotecas externas para el uso de strings ni de sus funciones, tales como `.lower()` o `.split()`. 

Históricamente, C fue diseñado alrededor de ASCII, donde cada caracter (`char`) ocupa 1 byte. Sin embargo, C23 tiene soporte para unicode mediante el header `<uchar.h>`. Esto introduce tipos específicos como `char8_t` (para unidades de código UTF-8), `char16_t` y `char32_t`. Además, C23 soporta literales codificados explícitamente usando prefijos, como `u8"cadena"` para forzar codificación UTF-8 en tiempo de compilación.

En cambio, en Python el soporte Unicode es nativo. El tipo primitivo `str` es una secuencia de code points Unicode. Python abstrae la codificación interna (usando 1, 2 o 4 bytes por carácter según sea necesario). Para trabajar a nivel de bytes como lo hace C (por ejemplo UTF-8), Python requiere realizar un encoding explícito hacia el tipo primitivo `bytes` (ej. `"cadena".encode('utf-8')`).

Dentro del manejo de la memoria, en C nos encontramos con las clasificaciones de Estatica, Automatica (stack) o Dinámica (heap). El programador es el encargado de reservar y liberar dicha memoria, lo que causa que un programador poco experimentado sea propenso a cometer errores relacionados al buffer, overflow, leaks, etc. Caso contrario, tenemos una gestión totalmente automática por parte de Python, donde internamente el lenguaje utiliza optimizadores como interning de string.

Sobre la mutabilidad e inmutabilidad del tipo string, en Python `str` es inmutable, debido a que cualquier operación que altere la cadena (concatenar o reemplazar por ejemplo) generan un nuevo objeto en memoria y devuelve una nueva referencia. En cambio, en C la mutabilidad depende de cómo y dónde se asigne la memoria para el arreglo de caracteres.

Si inicializamos la cadena copiando un literal a un array local (`char str[] = “Hola”;`), la memoria se reserva en Stack y es mutable. Sin embargo, si la inicializamos haciendo que un puntero apunte directamente a un literal cadena (`char *str = “Hola”;`), es inmutable. En C23, intentar mutar un literal cadena a través de su puntero resulta en un comportamiento indefinido, ya que el compilador los aloja en memoria de solo lectura.

En Python los string son objetos first class citizen que pueden ser asignados a variables, pasados como argumentos y retornados como por funciones manteniendo su identidad como objeto. En cambio en C al no existir sino arreglos de `char` estos no son first class citizen, no pudiendo, por ejemplo, ser retornados por valor desde funciones ni ser asignados directamente entre sí. Estos arreglos se gestionan con punteros trabajando de manera directa con la memoria. Cuando se desea pasar uno como argumento a una función lo que en realidad se pasa es una copia al puntero del primer carácter del arreglo. A diferencia de Python que lo que pasa es una referencia al objeto string.

Al no existir el tipo string una función no puede devolver un arreglo por valor, sino que lo que devuelve es un puntero al mismo. Debe tomarse en cuenta que no es válido retornar un puntero a un arreglo local dentro de la función debido a que este se aloja en el Stack y se libera una vez que la función termina por lo que una forma de retorno es reservar memoria con `malloc` en el Heap y retorna el puntero de la misma, en esta situación queda en responsabilidad del programador liberar la memoria con `free` posteriormente. En cambio en Python los string son objetos que la función puede retornar por referencia sin trabajar con la memoria directamente pues esta es gestionada por el sistema de gestión de memoria del lenguaje, además al ser el string inmutable no existe el riesgo de que objeto retornado sea modificado inesperadamente.
